# isostress 服务器版

> **状态：实现已落地。** 数据面（帧解析、等候池配对、静默丢弃、字节中继）已按 isostress 1.0.0
> 线上规范用 Rust 实现并验证。L4 扩展（离线投递、群组、身份目录）实现在**独立控制面**上，
> 不触碰线上帧格式。

| 项 | 值 |
|---|---|
| 适用规范 | 《isostress 协议总指导》1.0.0 |
| 语言 | Rust（edition 2021，MSRV 1.80） |
| 产物 | 单文件静态二进制，`aarch64` / `x86_64` 双架构 |
| 运行时依赖 | 无（不需要数据库、消息队列、TLS 终结器） |
| 服务端版本 | `ISOSTRESS_SV-1.0.0-20261030` |
| 许可 | AGPL-3.0-or-later **或** 商业授权 |

## 这是什么

给 isostress 客户端做中继的服务器。它只增加一个角色：**酒店前台**。

```
对端 A ──┐                                   ┌── 对端 B
         ├──── isostress 服务端（本仓库）────────┤
对端 C ──┘        配对 + 字节中继            └── 对端 D
                  服务器全程不解密
```

服务器只做三件事：**登记、配对、转发**。它从不拆箱：阶段二的公钥、阶段三的确认标签、
阶段四的密文，对它全是不透明字节。它唯一读取的是阶段一帧里的两个令牌哈希（用于配对）
和阶段四头里的会话 ID（用于房间路由）。

## 这不是什么

- **不是 CA**。令牌签发与撤销（TCA / CRL）是另一个独立角色。本仓库既不签发也不撤销身份。
- **不是解密中间盒**。任何终结握手的实现都会让服务器变成明文可见点，明确不在范围内。
- **不做持久化**。离线信封与群组日志只存在于内存，进程重启即失。持久化是部署决定，不是协议决定。

## 为什么需要服务器版

客户端版是直连模型：通信双方必须各自可达。这在互信小圈子里够用，但解决不了：

- 一方在 NAT 之后且无法做端口映射；
- 需要异步投递（对方离线时消息仍能送达）；
- 需要多方群组、身份目录或跨组织联邦；
- 需要在不暴露彼此 IP 的前提下建立连接。

本仓库在不削弱端到端安全属性的前提下补齐上述能力，并保持与客户端协议的互操作。

## 快速开始

```bash
cargo build --release
./target/release/isostress-server --listen 0.0.0.0:7443
```

带控制面（生产建议，并且务必设 token）：

```bash
./target/release/isostress-server \
  --listen 0.0.0.0:7443 \
  --control 127.0.0.1:<port> \
  --control-token "$(head -c 32 /dev/urandom | base64)" \
  --profile advanced
```

`<port>` 由部署方或实现默认值决定，示例值不构成约定。

## 配置档位（附录 B.2）

| 档位 | 并发 | 单 IP | 离线消息 | 群组 | 身份目录 | 空闲超时 |
|---|---|---|---|---|---|---|
| `beginner` | 2000 | 32 | 保留 1 天 | 32 人 | **关闭** | 不超时 |
| `advanced` | 20000 | 128 | 保留 7 天 | 256 人 | **关闭** | 不超时 |
| `high-anonymity` | 500 | 4 | **关闭** | **关闭** | **关闭** | 300 秒 |

身份目录在**所有档位默认关闭**：它记录的是「某个令牌哈希何时出现过」，这属于规范第 979
行禁止记录的配对信息。打开它是运营者显式选择的一次偏离，服务端启动时会打印警告。高匿名档
另外关闭离线消息与群组。

控制面（L4）默认不监听；一旦启用，**必须提供口令**，否则进程直接退出。

## 服务端处理流程（对照 §4.2 四步）

| 步骤 | 规范要求 | 本实现 |
|---|---|---|
| 1. 参数核对 | 形状不符即拒 | 长度与结构校验（`src/frame.rs`） |
| 2. 令牌验证 | TCA 签名 + CRL | **不实现** —— 属 TCA/CRL 角色 |
| 3. 等候池匹配 | 查找持有 H(Token_A) 的住客 | `src/lobby.rs` |
| 4. 等候池管理 | 30 秒自动清除、不广播 | `lobby_timeout_secs` + `Lobby::withdraw` / `Lobby::sweep` |

配对判据是**双向匹配**：

```
新来者.src == 已在等者.dst   且   新来者.dst == 已在等者.src
```

单向撞名不会接通，因此攻击者无法靠猜目标哈希把自己塞进别人的会话。

## 安全边界

| 性质 | 实现方式 |
|---|---|
| 服务器看不到内容 | 全程不持有任何会话密钥，只转发密文 |
| 不记录配对信息 | 规范第 978 行【强制】；日志只有聚合计数，无令牌哈希 / IP / 会话 ID |
| 身份冒用无效 | 配对要求双向匹配 |
| 探测不可区分 | 任何异常一律静默丢弃：不回字节、不断线、不报错 |
| Slowloris | 阶段一整帧共享 15 秒截止时间，不是每次 recv 重新计时 |
| 内存炸弹 | 所有长度字段先校验上限再分配 |
| 流量分析 | 身份目录时间粗化到整分钟；默认禁止任意哈希查询 |

完整的操作者能力边界见 [`../docs/THREAT-MODEL.md`](../docs/THREAT-MODEL.md)。

## 适用关系（多对多）

总指导版本与实现版本**不是**一对一：

| 关系 | 规则 |
|---|---|
| 一个总指导 → 多个实现 | 协议行为未变就共用一条声明 |
| 多个总指导 → 一个实现 | 在 `APPLIES_TO_DOC_VERSIONS` 里逐项列出 |
| 版本号相同、实现不同 | 版本号相同不等于实现相同，也不构成兼容主张 |
| 兼容性判定 | 真实兼容始终由阶段三确认标签检查给出 |

握手帧**不携带版本串**：阶段一参数 JSON 与阶段四 AAD 都不含版本或协议标识字段。
